# Portfolio review (13-14 Nov 2026)

Why the site has the projects, the lead and the card order it has. The method is The Interview Guys'
"Top 25 Claude Portfolio Prompts That Get You Hired" (2026-09-17), applied to real facts only. Every
figure below is copied from the project's README as it stood on 13 Nov 2026.

Target roles: forward-deployed engineer, AI engineer, software engineer.

## 1. Inventory

Each repository in `~/Projects` is scored 1 to 5 on relevance to the target roles, measurability (a
figure on data the author did not tune on), and ownership (how clearly the work and the decisions are
the owner's). All are solo repositories; commits are co-authored with Claude, which a hiring manager
may ask about (see Open questions).

| project | relevance | measurability | ownership | verdict | why |
|---|---|---|---|---|---|
| fieldgate | 5 | 5 | 5 | must | Held-out receipts (200), a public dataset, a statistical guarantee tested by simulation, a documented change of course. |
| redactgate | 5 | 4 | 5 | must | 2,891 test documents and a named baseline (Presidio). The data is synthetic, so 4 not 5. |

What a hiring manager would expect and does not find: a result on a real customer's data, a live
deployment someone else uses, and a team project. All three are stated as limits on the pages rather
than hidden.

## 2. Signature project

**Lead: fieldgate.** It is the only project that answers the question an FDE is hired to answer for a
customer ("which outputs can skip a person, and how sure are we?") with a held-out measurement, a
method from the literature (Learn-then-Test), and a guarantee checked by simulation. It already leads
the homepage (the interactive pass mark), so the projects page and the homepage tell one story.

Runners-up and why they are not the lead:

- **ndacheck** has the cleanest test hygiene, but its headline (73.8% against 65.9%) is a modest gain,
  and its weakest answers are the ones a business cares about.
- **redactgate** has the largest sample and a named competitor, but the data is synthetic and 24.0% of
  documents still leak.
- **longhaul** is the most on-trend subject, but it **looks stronger than it is**: every dollar figure
  is modelled and the memory scores come from a mock reader. It must never be presented as a live
  result.
- **invoice-check** also looks stronger than it is: 20 of 20 sounds perfect, but the 20 invoices were
  generated by the same person who wrote the rules.

## 3. Audience map

| reader | wants in their time | loses trust when | what the site does |
|---|---|---|---|
| 30-second recruiter | the role, one strong result, a link to code | jargon, no role named, a wall of numbers | Homepage h1 and closing name the roles; projects.html opens with eight cards, one figure each; About and skill: proof lines sit one screen below. |
| Hiring manager (2 minutes a project) | the problem, the owner's decisions, a measured result and its limit | results without sample sizes, no failures, claims they cannot check | One case page per project: problem, figure with its sample, limit, then SOAR, the one decision and what was dropped, then how to run it and where the figure is written. |
| Specialist (ML or security peer) | test-split hygiene, baselines, reproducible commands | a test split used for tuning, a rounded-up figure, a hidden limit | Each page names the file the figure comes from and the command that writes it; dev/test use is stated where the README states it (noticeday's seven test runs, mcp-pin's burned held-out set). |

## 4. Card order on projects.html

Two screens of four cards.

1. **First screen, document and privacy work with the strongest evidence:** fieldgate (lead),
   redactgate (largest sample, named baseline), ndacheck (real NDAs, baseline), noticeday (real
   contracts, human confirmation).
2. **Second screen, "Agents, security and invoices":** mcp-pin (real unseen data, so first in the row),
   longhaul (relevant but modelled), Knowledge system (red team, small live samples), invoice-check
   (product depth, synthetic data, so last).

The rule: within each screen, stronger evidence first. A recruiter who reads only the first row sees
four held-out or real-data results.

## 5. Case pages (prompts 5, 6, 7, 9)

`projects/<name>.html`, one per card, four screens each:

1. Problem in one sentence, the one figure with its sample size, the one limit, the repository button,
   and real UI: the redactgate, ndacheck and noticeday screenshots from their `docs/`; the homepage's
   kit fragments for fieldgate, longhaul and the Knowledge system; real terminal output for mcp-pin
   and invoice-check.
2. SOAR (situation, obstacle, action, result) and the constraints (CPU, budget, public data).
3. The one key decision and what was dropped (a failed attempt where the README documents one; for
   invoice-check, the rejected alternative, labelled as such).
4. How to run it (commands copied from the README) and the file the figure comes from.

Each page ends by linking the next project in the card order.

## 6. Copy (prompts 10 to 13)

- **One-line bio (chosen):** "AI engineer who measures how often a system is wrong before anyone
  relies on it." Alternatives considered: "I build AI systems and publish how often they are wrong."
  / "AI engineer: documents, agents and private data, each with a measured error rate." /
  "Forward-deployed AI engineer who ships the check along with the model." / "I measure AI systems
  before customers rely on them."
- **About:** on projects.html, not the homepage: the homepage must stay its current length.
- **Headlines:** each case page's h2s lead with the decision or the problem in plain words ("A
  certified cut, not the one that looked fine", "Placeholders, not deletions", "A near match never
  passes an invoice").
- **Skill: proof:** six lines on projects.html, each linked to the case page that proves it.

## 7. Stress tests (prompts 18, 19, 21)

Run as three subagents on the finished pages; findings and fixes are recorded below.

### 18, skeptical recruiter

| finding | fix |
|---|---|
| fieldgate's 17.2% to 2.7% hides the trade-off and that the reporting set was seen during development | Case page now says 47% of fields were approved alone at the 5% target, the rest went to a person, and that the reporting set was seen while the signals were chosen. |
| fieldgate's receipt and queue show simulated scores without saying so | The decision text says so. |
| noticeday headlines its best field and drops the 2 false alarms and the repeated test runs | Figure now carries "2 false alarms"; the limit gives the send-notice-by date (3 of 10) and says the test split has been run seven times. |
| mcp-pin's 0.18% reads as a measurement on tool descriptions; detection on unseen attacks is unmeasured | "3,288 description strings", "a rough figure: 4 of the 6 were not tool descriptions"; the limit says the catch rate on unseen attacks is unmeasured. |
| redactgate hides the five looks at the test split, its precision floor and that Presidio ran on defaults | All three are on the page now (65.1% floor, about 88% from a hand check of 100 masks; five test runs, one per version; "Presidio with custom recognisers would close much of the gap"). |
| ndacheck: "a person reads only the flagged points" overstates | Now "starts from the quoted clauses"; the decision adds that quoted answers can still be wrong. |
| Knowledge system: 18 of 18 hides the 26; 160 of 160 is enforced, not measured | Figure line gives the other 8 and the live result; the result card says the validator refuses any quote it cannot find. |
| invoice-check: "20 of 20 planted problems" miscounts (7 are clean) and the templates were written for the fixtures | Card and page say 7 of them clean; the limit says the templates were written for these invoices. |
| "Evaluation design ... every score" generalises ndacheck to all eight; "Shipping software" overclaims | Scoped to ndacheck; "Building software". |
| Homepage FAQ: "each pipeline in CI" is true only of longhaul; "3 projects leave out" answered 2 | Both fixed without changing the homepage's length. |
| longhaul: "no API key" reads as an excuse beside paid runs elsewhere | Kept (it is the README's reason), moved into the cache explanation. Running the live pilot is an owner decision. |
| No contact path; homepage leads with the research projects; Godot question | Not changed: the brand allows only the GitHub link, and the homepage stays as it is. Listed under Open questions. |

### 19, vagueness detector

Plain words now stand beside every term a hiring manager may not know: Learn-then-Test (what it does in one
sentence), held out ("kept aside and never used to build or tune it"), token probability and re-samples,
NLI, F1 (replaced by "44 of 95 true no answers right" on dev), the precision floor, NER and check digits,
MCP and the SHA-256 fingerprint, the prompt cache and why a pause changes the bill, the mock reader
("reads perfectly, so a real model can only do worse"). "A rug pull caught in CI" became "A changed tool
description, caught in CI". The About now names the four CPU projects instead of "most", and the work
wanted names the processes (receipts, invoices, NDAs, renewal dates).

### 21, weak-link finder

1. **Most likely rejection: no way to reach or verify the candidate.** Only a private GitHub profile.
   Not fixable on the site under the brand rules (GitHub only); see Open questions.
2. **No real customer or user.** Stated, not hidden, on every page; the About now says "a question I
   expect a customer to ask" rather than implying customers.
3. **Credibility nicks** (invoice-check count, knowledge 18 of 26, noticeday sample reading as 102):
   fixed as above.

Navigation: the projects page's skip link pointed at the homepage (fixed). The homepage's knowledge
section has no inline link to its case page: adding one pushed the section past two screens at 1024
and 820, so it is reached from the footer and the projects page instead.
