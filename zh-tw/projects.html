專案。每個一個數字、一項限制。

fieldgate

在 CPU 上讀取掃描收據，並決定哪些欄位可以不經人工。

在保留測試集的 200 張收據上，錯誤核准率從 17.2% 降到 2.7%。

限制：只有一個收據資料集和一個模型。

閱讀案例研究

redactgate

在你把文字貼進 ChatGPT 或 Claude 之前，先拿掉其中的姓名、卡號和 IBAN，再於回覆中放回去。

在 2,891 份測試文件上遮蔽了 84.1% 的個人資料值。Presidio 預設設定：52.7%。

限制：仍有 24.0% 的文件洩漏至少一個值，因此需要人工檢查。

閱讀案例研究

ndacheck

回答關於保密協議（NDA）的 17 個標準問題，並引用每個答案所依據的條款。

在保留測試集的 123 份 NDA 上正確率 73.8%，而一律給出常見答案的基準為 65.9%。

限制：風險最高的「否」答案，正是表現最弱的部分。

閱讀案例研究

noticeday

找出自動續約合約的最後解約日。每個日期都由人工確認後才放進行事曆。

在 13 份經律師標註的測試合約中，解約通知期有 11 份正確、0 份錯誤、2 次誤報。

限制：到期日是弱點，59 份中只對 26 份。

Agent、資安與發票

mcp-pin

當 MCP 伺服器的工具定義改變時讓 CI 失敗，並掃描工具描述中隱藏的提示詞注入。

在來自五個未見過伺服器的 3,288 則描述上，誤報率 0.18%。

限制：它抓得到已知的注入模式，但不是每種改寫都抓得到。

閱讀案例研究

longhaul

以四種上下文策略為一個 120 輪的 Agent 班次計算成本，快取讀取與寫入分開計算。

關閉快取時，完整歷史的成本約高出 15 倍。

限制：成本是建模估算的。目前還沒有用真實模型執行過。

閱讀案例研究

知識系統

Agent 提議附有引文的筆記，程式碼查核每一則引文，最後由人工核准。

在 26 次紅隊攻擊中，需要禁止動作的 18 次全數被程式碼擋下。

限制：只用了一個人的筆記庫。搜尋只在作者自己寫的 20 個問題上測試過。

閱讀案例研究

invoice-check

逐行比對供應商發票與採購單，並標出每個值是從頁面上哪個位置讀到的。

20 份測試發票全部依設計分類，其中 7 份無異常，且沒有多出任何項目。

限制：發票是合成資料，還沒有真實發票跑過。

關於 Eagle

在任何人依賴系統之前，先量測它多常出錯的 AI 工程師。

我打造處理文件、AI Agent 與私人資料的 AI 系統，然後測試它們。這裡的每個專案，都在回答一個我預期客戶在信任系統前會問的問題：我能查核它的成果嗎？它要花多少錢？會洩漏什麼？什麼時候仍需要人工檢查？

fieldgate、redactgate、ndacheck 和 noticeday 都在筆電 CPU 上，以開源模型和公開資料集執行。每份 README 都說明數字如何量測，以及這個數字「無法」說明什麼。

我想從事前線部署工程或 AI 工程工作：接手一項緩慢的人工檢查（收據、發票、NDA、續約日期），交付一個錯誤率經過量測的成果，並清楚說明它的極限在哪裡。

  • 評測設計：在 ndacheck 中，門檻值以訓練資料擬合、分數旁附上基準，且測試集評分後不再做任何調整。ndacheck
  • 人工審核分流：每個收據欄位都有自己的核准門檻，選定標準是讓錯誤核准率維持在目標以下；從 17.2% 降到 2.7%。fieldgate
  • LLM 資安：18 次紅隊攻擊全數被程式碼擋下；MCP 工具定義在 CI 中鎖定。知識系統 mcp-pin
  • 隱私工程：個人資料在送出提示詞前就於使用者的電腦上遮蔽，84.1% 對比 Presidio 的 52.7%。redactgate
  • Agent 成本：在 Inspect AI 上為一個 120 輪的班次計算成本，快取讀取與寫入分開計算。longhaul
  • 軟體開發：noticeday 有一個唯讀的 MCP 伺服器，讓 Claude 列出期限；invoice-check 的帳號彼此看不到對方的發票，並有 132 項在真實 PostgreSQL 上執行的測試。noticeday invoice-check
