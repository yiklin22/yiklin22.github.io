fieldgate。哪些收據欄位可以不經人工。

財務團隊不能憑「模型說它很有把握」就簽核。fieldgate 讀取掃描收據、為每個欄位評分，並為每個欄位挑出它可以自行核准的最低分數，同時讓錯誤核准率維持在目標以下。

2.7%

的自動核准值是錯的；這是在 200 張保留下來、從未用於建構或調校的收據上量得（843 個中有 23 個），若全部核准則是 17.2%。在這個 5% 的目標下，47% 的欄位直接核准，其餘交給人工。

限制：只有一個收據資料集和一個 1.7B 模型。目前還沒有整張收據能跳過審核：品項數只有 51% 的時候是對的。

從有把握的模型，到經過查核的門檻

情境

模型讀取一張收據，回傳總計、稅額和找零。大多數的值是對的。財務團隊要問的是：哪些值可以不經人工檢查就付款？

阻礙

模型自己聲稱的信心度，分辨對錯的能力還不如擲硬幣。若只因某個門檻在挑選它的那批收據上看起來不錯就採用，大約每十次有四次會超出目標。

行動

每個值都有四類共 20 個訊號：模型對自己寫下的值給出多高的機率、3 次重複作答是否一致、這個數字是否印在頁面上、收據是否加總相符。另有 400 張收據只用來為每個欄位挑選門檻。

結果

在 200 張保留的收據上，以 5% 為目標時，已核准欄位中的錯誤值比例從 17.2% 降到 2.7%，且 47% 的欄位無需審核即獲核准。每個欄位都維持在目標以下。

條件限制：一個 17 億參數的開源模型、不用 API 金鑰、一個公開資料集（CORD v2）。

經過認證的門檻，而不是看起來還行的那個

決策

每個欄位的門檻都來自一個已發表的方法：Learn-then-Test。它從嚴到寬逐一嘗試門檻，並停在第一個「用於挑選門檻的保留收據已無法以 95% 信心證明錯誤率低於目標」的地方。三組各自獨立的收據分別用來擬合評分器、挑選門檻、回報每個數字；不過在確定訊號清單時，回報用的那組曾被看過。本頁的收據與佇列以模擬分數示範這個概念。

捨棄了什麼

第一版在只有幾十個值的地方就開始認證流程，在那裡只要一個錯誤就會中止。結果折扣欄位在 2% 和 5% 時獲得認證，在 10% 時卻什麼都沒有，這不可能是對的。於是起點被移動，現在有一項測試確保較寬鬆的目標永遠不會核准得更少，整個分析也重跑了一次。

自己執行 fieldgate

需要 Python 3.11 以上版本和約 10 GB 磁碟空間；不需要 GPU。41 項測試不需要模型或資料。在 8 核心上每張收據擷取約需 13 秒，每個階段都會快取並可續跑。

數字從哪裡來

docs/results/cord.md，由 python -m fieldgate.analyze 根據快取的執行結果產生。信賴區間以收據（而非欄位）為單位做 bootstrap。

閱讀 README 與完整結果

fieldgate / 終端機
$ pip install -e ".[pipeline,app]"
$ python -m unittest discover -s tests -t .  # 41 tests, no model or data needed
$ python -m fieldgate.fetch  # CORD v2, about 2.3 GB
$ hf download Qwen/Qwen3-1.7B --local-dir .cache/models/Qwen3-1.7B
$ python -m fieldgate.run ocr --splits train validation test
$ python -m fieldgate.run extract --model .cache/models/Qwen3-1.7B --samples 3 --splits train validation test
$ python -m fieldgate.analyze --json docs/results/cord.json --out docs/results/cord.md
$ python -m fieldgate.app build --alpha 0.05  # route the held-out receipts
$ python -m fieldgate.app serve  # http://127.0.0.1:8770
