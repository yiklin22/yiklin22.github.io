ndacheck. A first pass over an NDA.

Every NDA review asks the same questions: may they hire our staff, must information be marked, may a copy be kept. ndacheck answers 17 of them and quotes the clause behind each answer, so a person starts from the quoted clauses instead of the whole NDA.

73.8%

of answers right on 123 held-out NDAs (2,091 answers), against 65.9% for always giving each question’s usual answer.

Limit: “no” answers, the ones a business cares most about, are the weakest: on the dev split it got 44 of 95 true “no” answers right. About one answer in four is wrong.

Open the repository
localhost:8850 / ndacheck

Seventeen questions, each with its clause

Situation

A first-pass NDA review is slow and repetitive, and a wrong “yes” on a clause banning the hiring of staff is costly. ContractNLI gives 607 real NDAs, each annotated for 17 questions with the clause behind the answer.

Obstacle

No fine-tuning on a CPU-only budget. An off-the-shelf model that judges whether a clause supports or contradicts a statement (NLI) does not read “shall not disclose to any third party” as contradicting a permission granted elsewhere in the same NDA.

Action

Keywords pick up to four candidate clauses per question, the NLI model scores each one, and thresholds fitted per question on the train split turn the scores into yes, no or not mentioned.

Result

73.8% right on the test split, against 65.9% for the usual-answer baseline, and ahead of it on 15 of 17 questions. The test set was scored three times, and nothing was tuned after any of them.

Constraints: a CPU, an off-the-shelf model of about 0.7 GB (cross-encoder/nli-deberta-v3-base), no fine-tuning, a public dataset (ContractNLI, CC BY 4.0), English only.

No clear clause means “check”, not a guess

The decision

When no clause clears its threshold, ndacheck gives the per-question default fitted on train and marks it “no clear clause, check”, with no quote. Every other answer quotes the clause it came from, so the reviewer checks one sentence per answer first. Answers with a quote can still be wrong.

What was dropped

Three fixes for the weak “no” answers, each fitted on train, raised train accuracy up to 76.6% but did not raise dev, so all three were dropped and the system left unchanged. Keyword rules that force “no” were dropped for the same reason. The likely real fix is a model fine-tuned on ContractNLI.

Run ndacheck yourself

Python, and about 0.7 GB for the NLI model, downloaded on the first run. The page takes pasted text, or a .pdf with a text layer, a .docx or a .txt. The evaluation needs ContractNLI, downloaded from Stanford.

Where the figure comes from

docs/results-test.md, written by scripts/evaluate.py --split test, with the per-question table against the baseline.

ndacheck / terminal
$ uv venv && uv pip install -r requirements.txt
$ source .venv/bin/activate
$ python -m ndacheck examples/sample_nda.txt  # add --json for machine-readable output
$ uvicorn ndacheck.app:app --port 8850  # web page at http://localhost:8850
$ pytest -q -m "not slow"  # fast tests (what CI runs)
$ python scripts/evaluate.py --split train --tune  # fit thresholds on train
$ python scripts/evaluate.py --split test  # writes docs/results-test.md
