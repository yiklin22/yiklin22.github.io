A restaurant’s prices, read only by the apps its owner allows

Situation

Owners already ask Claude or ChatGPT about their business, but their invoices and prices live in Marley. An MCP endpoint lets those apps read them directly, instead of the owner copying figures across.

Obstacle

Spending data is private, and any app can register itself under any name. Each app has to be allowed by the restaurant’s owner, see only that restaurant, and lose access the moment the owner disconnects it.

Action

OAuth 2.1 on the MCP SDK’s handlers: dynamic registration with https redirects only, PKCE S256 required, the resource pinned to this server’s /mcp, and a five-minute one-time code bound to the client, redirect, PKCE challenge and restaurant.

Result

73 tests pass. Codes, tokens and client secrets are stored hashed, refresh tokens rotate on every use, and owners list and disconnect apps under Account. A separate review of the branch found issues, fixed and tested on the same branch.

Constraints: FastAPI and the MCP Python SDK, the existing emailed-code sign-in, guest sessions that must never connect an app, and everything off unless PUBLIC_URL is set.

Consent happens on Marley, in the browser that asked

The decision

Authorize sends the browser to Marley’s connect screen, where only an owner with an account signs in with the emailed code and taps Allow; a guest never can. A cookie set at authorize ties the request to that browser, and Allow names the restaurant the screen showed, so a browser that has since signed in to another restaurant is asked again.

What it refuses

Any tool that writes: the six tools are the read-only ones Marley’s own chat uses. Errors go back only to the known Claude and ChatGPT callbacks; for any other app they stay on Marley, and the consent screen warns when the app’s redirect host is not claude.ai or chatgpt.com.
