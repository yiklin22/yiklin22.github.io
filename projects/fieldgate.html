fieldgate. Which receipt fields can skip a person.

A finance team cannot sign off on “the model said it was confident”. fieldgate reads scanned receipts, scores every field, and picks, per field, the lowest score it may approve on its own while wrong approvals stay under a target.

2.7%

of auto-approved values wrong on 200 receipts kept aside and never used to build or tune it (23 of 843), against 17.2% if every value were approved. At this 5% target, 47% of fields were approved alone; the rest went to a person.

Limit: one receipt dataset and one 1.7B model. No whole receipt can skip review yet: the item count is right only 51% of the time.

From a confident model to a checked cut

Situation

A model reads a receipt and returns its total, tax and change. Most values are right. The question a finance team asks is which ones can be paid without a person looking.

Obstacle

The model’s own stated confidence was worse than a coin flip at telling right from wrong. A cut chosen because it looked fine on the receipts used to choose it overshot its target about four times in ten.

Action

Every value gets 20 signals of four kinds: how likely the model rated the value it wrote, whether 3 repeat answers agree, whether the number is printed on the page, whether the receipt adds up. 400 receipts are used only to choose each field’s cut.

Result

On the 200 kept-aside receipts, wrong values among approved fields fell from 17.2% to 2.7% at a 5% target, with 47% of fields approved without review. Every field stayed under its target.

Constraints: a 1.7-billion-parameter open model, no API key, a public dataset (CORD v2).

A certified cut, not the one that looked fine

The decision

Each field’s cut comes from a published method, Learn-then-Test. It tries cuts from strict to loose and stops at the first one where the receipts set aside for choosing cuts can no longer show, with 95% confidence, that errors stay under the target. Three separate sets of receipts fit the scorer, choose the cuts and report every number, though the reporting set was seen while the list of signals was settled. The receipt and queue on this page show the idea with simulated scores.

What was dropped

The first version started the certification walk on a few dozen values, where one error ends it. It certified the discount field at 2% and 5% but at nothing at 10%, which cannot be right. The start was moved, a test now checks that a looser target never approves less, and the whole analysis was run again.

Run fieldgate yourself

Python 3.11 or later and about 10 GB of disk; no GPU. The 41 tests need no model or data. Extraction takes about 13 seconds a receipt on 8 cores, and every stage caches and resumes.

Where the figure comes from

docs/results/cord.md, written by python -m fieldgate.analyze from the cached run. Intervals are bootstrapped over receipts, not fields.

fieldgate / terminal
$ pip install -e ".[pipeline,app]"
$ python -m unittest discover -s tests -t .  # 41 tests, no model or data needed
$ python -m fieldgate.fetch  # CORD v2, about 2.3 GB
$ hf download Qwen/Qwen3-1.7B --local-dir .cache/models/Qwen3-1.7B
$ python -m fieldgate.run ocr --splits train validation test
$ python -m fieldgate.run extract --model .cache/models/Qwen3-1.7B --samples 3 --splits train validation test
$ python -m fieldgate.analyze --json docs/results/cord.json --out docs/results/cord.md
$ python -m fieldgate.app build --alpha 0.05  # route the held-out receipts
$ python -m fieldgate.app serve  # http://127.0.0.1:8770
