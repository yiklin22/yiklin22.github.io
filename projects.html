Projects. One figure and one limit each.

fieldgate

Reads scanned receipts on a CPU and decides which fields can skip a person.

Wrong approvals fell from 17.2% to 2.7% on 200 held-out receipts.

Limit: one receipt dataset and one model.

Read the case study

redactgate

Takes names, card numbers and IBANs out of text before you paste it into ChatGPT or Claude, then puts them back in the answer.

84.1% of personal values masked on 2,891 test documents. Presidio’s defaults: 52.7%.

Limit: 24.0% of documents still leak a value, so a person checks.

Read the case study

ndacheck

Answers 17 standard questions about an NDA and quotes the clause behind each answer.

73.8% right on 123 held-out NDAs, against 65.9% for always giving the usual answer.

Limit: “no” answers, the risky ones, are the weakest.

Read the case study

noticeday

Finds the last day to cancel an auto-renewing contract. A person confirms each date before it goes on the calendar.

Notice period right in 11 of 13 lawyer-annotated test contracts, none wrong, 2 false alarms.

Limit: the end date is the weak point, right in 26 of 59.

Read the case study

Agents, security and invoices

mcp-pin

Fails CI when an MCP server’s tool definitions change, and scans their descriptions for hidden prompt injection.

0.18% false alarms on 3,288 descriptions from five unseen servers.

Limit: it catches known injection shapes, not every rewording.

Read the case study

longhaul

Prices a 120-turn agent shift under four context strategies, with cache reads and writes counted apart.

Full history costs about 15 times more with the cache off.

Limit: costs are modelled. There is no live-model run yet.

Read the case study

Knowledge system

An agent proposes notes with quotes, code checks every quote, and a person approves.

18 of 18 red-team attacks that need a forbidden action stopped by code, out of 26.

Limit: one person’s vault. Search was tested on 20 questions the builder wrote.

Read the case study

invoice-check

Compares supplier invoices with purchase orders line by line and shows where on the page each value was read.

20 of 20 test invoices sorted as built, 7 of them clean, with nothing extra.

Limit: the invoices are synthetic. No real invoice has been through it.

Read the case study

About Eagle

AI engineer who measures how often a system is wrong before anyone relies on it.

I build AI systems for documents, agents and private data, then test them. Each project here answers a question I expect a customer to ask before trusting one: can I check its work, what does it cost, what leaks, and when does a person still have to look.

fieldgate, redactgate, ndacheck and noticeday run on a laptop CPU with open models and public datasets. Each README says how its figure was measured and what the figure does not show.

I want forward-deployed or AI engineering work: take a slow manual check (receipts, invoices, NDAs, renewal dates), ship something whose errors are measured, and say plainly where it stops.

  • Evaluation design: in ndacheck, thresholds fitted on training data, a baseline beside the score, and nothing tuned after the test set was scored. ndacheck
  • Human review routing: each receipt field gets its own approval cut, chosen so wrong approvals stay under target; 17.2% fell to 2.7%. fieldgate
  • LLM security: 18 of 18 red-team attacks stopped by code; MCP tool definitions locked in CI. Knowledge system mcp-pin
  • Privacy engineering: personal data masked on the user’s machine before the prompt, 84.1% against Presidio’s 52.7%. redactgate
  • Agent cost: a 120-turn shift on Inspect AI priced with cache reads and writes counted apart. longhaul
  • Building software: noticeday has a read-only MCP server that lets Claude list deadlines; invoice-check has accounts that cannot see each other’s invoices and 132 tests on a real PostgreSQL. noticeday invoice-check
